# OpenAI 上游图片优化与 Zstd 压缩

Sub2API 的 OpenAI OAuth HTTP 出站插件。保留旧插件 ID 和签名发行方。运行时是 Linux amd64 静态二进制。

## 安装与升级

1. 在 Sub2API 插件管理上传签名的 `openai-upstream-zstd-1.4.0-linux-amd64.s2plugin`。首次安装时按[安装说明](docs/guidebook/install.md)登记公钥。
2. 打开配置页读取旧配置。图片优化初次安装时默认关闭。升级时沿用已保存的设置，新增的换图请求体上限初始为 64 MiB。
3. 开启图片优化，从一个新 HTTP 对话发送 JPEG 或 PNG，再在同一个对话续轮。

## 图片设置

| 尺寸档 | 横图上限 | 竖图上限 | 画质预设 |
|---|---|---|---|
| 1080p（默认） | 1920 × 1080 | 1080 × 1920 | Q86 |
| 1440p | 2560 × 1440 | 1440 × 2560 | Q92 |
| 原尺寸重编码 | 原尺寸 | 原尺寸 | Q86 |

两档缩放都等比缩小，保留整张画面和档内原尺寸。长短边比达到 3:1 时按原尺寸重编码。画质可设 1–100。

候选 JPEG 比原文件至少节省 32 KiB 时替换。比较的是 Base64 解码后的文件字节。门槛设为 0 时，只要候选更小就替换。旧版的长边上限和双门槛会迁移到默认尺寸档和新门槛。

「最大换图请求体」按整条出站 JSON 的字节计算，单位是 MiB。默认 64 MiB，填 0 表示不限。换图与 zstd 各自判断请求体上限。

JPEG 上限 32 MiB、4800 万像素，PNG 上限 24 MiB、2400 万像素。两者单边最多 12000 px。透明或 16 位 PNG、动画、坏图和超限图透传。

插件识别最终 Codex Responses 中的用户 `input_image` 和函数或自定义工具的结构化图像。坐标工具返回保留原图。显式 `detail: original` 和结构化工具图像保留尺寸。JPEG 的 EXIF 方向在重编码前应用到像素。其余 JSON 字节和独立 `/v1/images/*` 请求透传。

图片失败时沿用原图并继续 zstd。HTTP 415 使用同一份 JSON 明文重试，后续冷却期间仍可换图。配置页显示原始、换图后及预计发送体积，并列出图片缓存与回退统计。

## 多轮和资源

首次决策跟随可识别的输入前缀。已有历史首次接入时保留原图。当前配置用于新图片，已记录图像按先前参数恢复。宿主提供 KV 时只保存摘要和首次决策，JPEG 结果始终留在有上限的进程内缓存。无法识别的历史、故障和超出图片资源限制的请求优先透传。

zstd 使用 level 3 和匿名临时文件。请求体上限默认 512 MiB，填 0 表示不限。同时处理的请求数可填写正整数，初始值为 2。插件处理的是出站 HTTP。上游账号、代理与流式响应沿原传输路径。

见[构建与验证](docs/development.md)。

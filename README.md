# OpenAI 上游图片优化与 Zstd 压缩

Sub2API 的 OpenAI OAuth HTTP 出站插件。保留旧插件 ID 和签名发行方。运行时是 Linux amd64 静态二进制。

## 安装与升级

1. 在 Sub2API 插件管理上传签名的 `openai-upstream-zstd-1.2.1-linux-amd64.s2plugin`。首次安装时按[安装说明](docs/guidebook/install.md)登记公钥。
2. 打开配置页读取旧配置。图片优化默认关闭，原有 zstd、大小上限与代理设置继续使用已保存值。
3. 开启图片优化，从一个新 HTTP 对话发送大 PNG 截图，再用同一个对话验证续轮。将关闭图片优化作为回退手段。

## 图片设置

| 设置 | 默认值 |
|---|---|
| JPEG 画质 | 92 |
| 长边限制 | 0，保留原尺寸。可填 2560 等比缩小普通图 |
| 最小文件节省 | 同时达到 25% 和 256 KiB，等于阈值时也通过 |
| PNG 范围 | 512 KiB–24 MiB、8 位静态不透明 PNG、最多 1200 万像素、每边最多 8192 px |

门槛比较解码 Base64 后的 PNG 与 JPEG 文件。512 KiB 的 PNG 至少节省 256 KiB 才替换，2 MiB 的 PNG 至少节省 512 KiB。每道门槛填 0 可解除该项限制，替换仍要求字节数减少。

插件识别最终 Codex Responses 中的用户 `input_image` 和函数或自定义工具的结构化图像。坐标工具返回保留原图。显式 `detail: original` 和结构化工具图像保留尺寸。其余 JSON 字节原样透传。JPEG 有损编码，请用实际小字截图核对效果。

图片失败时沿用原图并继续 zstd。HTTP 415 使用同一份 JSON 明文重试，后续冷却期间仍可换图。配置页显示原始、换图后及预计发送体积，并列出图片缓存与回退统计。

## 多轮和资源

首次决策跟随可识别的输入前缀。已有历史首次接入时保留原图。当前配置用于新图片，已记录图像按先前参数恢复。宿主提供 KV 时只保存摘要和首次决策，JPEG 结果始终留在有上限的进程内缓存。无法识别的历史、故障和超出图片资源限制的请求优先透传。

zstd 继续使用 level 3、默认 512 MiB 上限、可填 0 不限、默认并发 2 和匿名临时文件。插件处理的是出站 HTTP。上游账号、代理与流式响应沿原传输路径。

见[构建与验证](docs/development.md)。

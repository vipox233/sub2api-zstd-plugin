# OpenAI 上游 Zstd 压缩插件 1.1.0

用于 Sub2API 的 OpenAI OAuth HTTP 出站请求压缩。Linux amd64，已编译安装包不需要 Go、Python 或额外容器。

## 本版改动

- 默认最大压缩请求体由 16 MiB 提高为 **512 MiB**。
- 去掉 64 MiB 硬上限和“上限 × 并发 ≤ 64 MiB”限制。可填 1024 或更大值；**0 表示不设插件请求体大小上限**。
- 并发满时等待压缩槽位，不再因并发满而发送未压缩的大请求。等待可被请求取消中止。
- 以 64 KiB 块处理请求；原文和压缩结果各自超过 1 MiB 后转为匿名临时文件。不按用户设定的上限预分配大数组。
- 保留 Zstd level 3、账号代理、SSE 流式转发、明确 HTTP 415 后的一次原文回退。网络错误不在插件内自动重发。

## 从 1.0.0 升级

1. 将包内 `trusted-publisher.yaml` 的新公钥合并到 Sub2API 现有 `config.yaml` 的 `plugins.trusted_publishers`，保留旧公钥和其他配置，重启 Sub2API 一次。
2. 在插件管理上传 `openai-upstream-zstd-1.1.0-linux-amd64.s2plugin`，更新同一插件并启用。
3. **打开配置页，把最大压缩请求体改为 `512` 或 `0`，然后保存。** 升级保留宿主已保存的配置，不会自动把你原来的 16/32 改成 512。

本次使用新签名密钥 `vipox-zstd-20261104`。旧签名私钥未包含在上一版交付件中，不伪造或复用旧签名。新包与旧包插件 ID 相同：`cn.vipox.openai-upstream-zstd`。

## 建议配置（5 Mbps 出口）

最小请求体 1024 字节；最大压缩请求体 **0**（不因插件大小阈值而跳过压缩）或 **512 MiB**；并发 **2**；响应头超时 600 秒；跟随账号代理。

## 重要边界

“0 不限”仅指本插件的大小筛选，不代表内存/磁盘无限，也不会绕过 CDN、OpenResty、Sub2API 或上游的请求大小限制。宿主可能仍会缓存完整原始请求，本插件只避免自己再创建同样大的堆内存副本。

临时文件使用插件运行环境的临时目录（通常为 `/tmp`）。需要可写和足够剩余空间；如果是 tmpfs，仍会占用内存。每请求最坏临时空间约为原文与压缩结果之和。文件创建后立即解除文件名连接，最后一个读取者结束或进程退出时由系统释放。磁盘不足则返回准备失败，不偷偷改发原文。

压缩是分块进行的，但会先准备完压缩结果，再以确定的 `Content-Length` 发送上游，不是边收边上传。并发槽位包含准备、上传和等待响应头，不包括后续 SSE 输出。

仍只针对官方 Codex Responses OAuth HTTP 请求；API Key 路径不适用，不直接压缩 WebSocket 帧。小请求、已编码请求、无压缩收益、非目标路径、显式非零大小上限和 415 冷却期仍可能原文转发。

未安装到线上服务，未使用真实 OpenAI 账号做端到端验证。测试范围见 `docs/validation.md`。出现不兼容时可在插件管理停用本插件，恢复宿主原生传输。
